## Project Overview

This is a **pure frontend** Markdown editor that integrates directly with GitHub API to provide a CMS-like experience for static blogs (Astro, Hugo, Hexo, etc.). It requires **no backend server** - all GitHub operations happen client-side.

## Development Commands

```bash
# Build runtime configuration (injects env vars into static files)
npm run build

# Start local development server (http://localhost:8080)
npm start

# Alternative start command
npm serve
```

**Critical**: Always run `npm run build` after changing environment variables. This generates `static-deploy/js/runtime-config.js` which injects configuration into the frontend.

## Environment Configuration

Required environment variables for GitHub integration:

- `MARKDOWN_EDITOR_GITHUB_TOKEN` - GitHub Personal Access Token (repo scope)
- `MARKDOWN_EDITOR_GITHUB_OWNER` - GitHub username/organization
- `MARKDOWN_EDITOR_GITHUB_REPO` - Target repository name

Optional image hosting variables (defaults to main GitHub config):

- `MARKDOWN_EDITOR_IMAGE_TOKEN` - Separate token for image repo
- `MARKDOWN_EDITOR_IMAGE_OWNER` - Image repo owner
- `MARKDOWN_EDITOR_IMAGE_REPO` - Image repository name
- `MARKDOWN_EDITOR_IMAGE_BRANCH` - Image branch (default: `main`)
- `MARKDOWN_EDITOR_IMAGE_DIR` - Image directory (default: `images`)
- `MARKDOWN_EDITOR_IMAGE_LINK_RULE` - CDN rule: `jsdelivr`, `statically`, or `github` (default: `jsdelivr`)

## Architecture

### Directory Structure

- **`static-deploy/`** - Source code directory (deployment root)
  - `index.html` - Entry point
  - `js/app.js` - Vue.js main application
  - `js/config.js` - Content types and metadata field definitions
  - `js/editor-manager.js` - Vditor editor initialization
  - `js/image-handler.js` - Image upload UI interactions
  - `js/mobile-utils.js` - Mobile viewport handling
  - `github-service.js` - GitHub API wrapper
  - `image-service.js` - Image compression and upload service
  - `css/` - Stylesheets (base, editor, components, mobile)

- **`public/`** - Build output (generated by `npm run build`, copy of `static-deploy/` with injected config)

- **`scripts/generate-runtime-config.js`** - Build script that reads environment variables and generates `runtime-config.js`

### Key Modules

**GitHub Service** (`github-service.js`):
- Pure frontend GitHub REST API client
- `getFile()` - Fetch file content with Base64 decoding
- `createOrUpdateFile()` - Create/update files with automatic Base64 encoding
- `publishContent()` - Auto-generates file paths based on content type (Blog → `src/content/posts/`, Essay → `src/content/essays/`)

**Image Service** (`image-service.js`):
- Browser-based image compression using Canvas API
- Uploads to GitHub repository
- Generates CDN links (jsDelivr, Statically, or GitHub Raw)
- Smart quality adjustment to meet target file size

**Config System** (`js/config.js`):
- Defines content types: `GENERAL`, `BLOG`, `ESSAY`, `GALLERY`
- Metadata fields per content type (title, categories, date, etc.)
- YAML frontmatter generation function

**Runtime Configuration**:
- Environment variables → `scripts/generate-runtime-config.js` → `static-deploy/js/runtime-config.js` → `window.RuntimeConfig`
- This prevents hardcoding tokens in source code while maintaining a static deployment

### Data Flow

1. User opens editor → App checks `window.RuntimeConfig` for GitHub credentials
2. Load content via URL param `?edit=path/to/file.md` → GitHub API fetch
3. User edits in Vditor → Real-time Markdown rendering
4. Image upload → Drag/paste → `image-handler.js` → `image-service.js` compresses → Upload to GitHub → Insert Markdown link
5. Publish → `app.js` collects metadata + content → `github-service.js` commits to GitHub → Triggers blog's CI/CD

## Content Types & Publishing

**Blog** (`src/content/posts/`):
- YAML frontmatter: title, categories, date, description
- Filename: `YYYY-MM-DD-slug.md`

**Essay** (`src/content/essays/`):
- YAML frontmatter: title, pubDate, mood, description
- Filename: `YYYY-MM-DD-slug.md`

**Gallery**:
- Image-first content type with auto-generated date metadata

**General** (`docs/`):
- Plain Markdown without frontmatter

## Mobile & PWA Support

- Fully responsive with mobile-specific CSS (`css/mobile.css`)
- PWA installable (service worker at `static-deploy/sw.js`)
- Mobile viewport fixes in `js/mobile-utils.js`
- Safe area support for notched devices

## Styling Architecture

**CSS Organization**:
- `base.css` - Core layout, variables, dark mode
- `editor.css` - Vditor editor customization
- `components.css` - UI components (buttons, dialogs, progress)
- `mobile.css` - Mobile responsive overrides (`@media (max-width: 768px)`)

**Dark Mode**:
- Default theme is dark (`isDarkMode: true` in app.js)
- Theme persisted in localStorage
- Vditor editor syncs with app theme

## Development Guidelines

- **一次修改完成之后,自动创建提交到远程仓库** (Auto-commit and push after each modification is complete)
- **尽量不添加测试和调试页面进行测试,除非我要求你进行测试** (Avoid adding test/debug pages unless explicitly requested)
- Primary source is `static-deploy/`, not `public/` (which is auto-generated)
- When modifying styles for mobile, edit `static-deploy/css/mobile.css`
- Test image upload requires valid GitHub token and repo configuration
- PWA features require HTTPS (use localhost for development)

## Tech Stack

- **Frontend**: Vue.js 2.x (CDN, no build step for app code)
- **UI Library**: Element UI
- **Editor**: Vditor (WYSIWYG/IR/SV modes)
- **API**: Native fetch (no axios)
- **Build**: Node.js script for config injection only
- **Deployment**: Vercel (or any static host)
